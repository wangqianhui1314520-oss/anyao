# 安药 0.4.6 Windows 适配版

本目录将授权 APK 中的原 H5 界面与药盒协议用于 Windows 桌面适配，并在另一个窗口打开当前 PILLBANK 展示网站。原 APK 与 Android 源码保持原样；这不是把 APK 二进制转换为 EXE。

`scripts/prepare-assets.py` 从指定的安药 0.4.6 APK 提取 `assets/app/` 下的九个文件到 `assets/`。它先检查固定 APK SHA-256 和 ZIP CRC，再逐字节复制；`assets/source-asset-manifest.json` 记录原路径、目标路径、字节数、CRC 与 SHA-256。运行时的 Windows 适配由本机服务器向 HTTP 响应注入，不能改写这些原始资产。

运行 `python scripts/prepare-assets.py --verify` 可只读复核原资产；运行 `node --test --test-isolation=none` 检查桌面源码与打包约束。离线打包脚本默认只执行预检，显式加 `--build` 后才生成发行包。它复用项目中已经安装的官方 Electron 33.2.0 Windows 运行库，不下载依赖、不修改运行库二进制。

发行目录为 `releases/anyao/anyao-desktop-0.4.6-linked/`。将 ZIP 全部解压到同一目录后，双击 **安药.exe**；必须保留同目录中的 DLL、`locales` 与 `resources`。遇到 `ELECTRON_RUN_AS_NODE` 或 `NODE_OPTIONS` 环境变量干扰时，可使用 `Start-AnyAO.cmd`。最终包包含桌面 `src`、保真的 `assets`、入口 `package.json` 和当前展示网站 `web`；哈希清单与 ZIP CRC 验证记录随发行产物保存。

## 模块插入即用的模拟演示

有两种入口：普通浏览器可独立演示外设插拔；安药 Windows 双窗口还可让原 App 的计划和协议帧驱动虚拟药盒。两者的会话与数据源分开，不能把独立网页的模块演示当成已经连上安药或真实硬件。

### 普通网页独立入口

打开网站的 `/?view=3d#hardware-lab`（本地默认地址为 `http://127.0.0.1:4187/?view=3d#hardware-lab`；部署在其他地址时保留该路径）。进入“联动实验室 → EXE 与 Web App”，找到“V0.9 · 全外设模块实验台”。普通网页无需先启动安药即可使用这块本页软件模型。

点击“触发模块模拟提醒”，观察八口驱动与输出状态，再拔出并插入屏幕、马达、音响或 LED。拔出对应能力关闭；插回后校验身份、加载匹配驱动并自动应用当前模拟提醒。最后点“结束模块模拟提醒”。这一步只改变网页本地模块状态，不发送真实 BLE 指令，不创建服药记录，也不读取患者数据。

### 安药与网站双窗口入口

保持安药顶部连接模式为“虚拟药盒 · 本机协议联调”。安药窗口发出原协议格式的 07 字节帧，独立虚拟外设解析并返回响应；网站窗口展示同一会话的状态，并提供模拟按键、盖子和模块插拔。此过程不使用无线蓝牙，也没有操作实际 Hi-PB1 的可拆硬件。

1. 在安药“健康 → 穿戴设备与同步”（或“我的 → 小米手环 / 手表”）打开设备页，点“连接设备”，选择列表中的虚拟药盒。网站“联动实验室 → EXE 与 Web App”应显示模拟连接及八个端口；初始模块全部处于“已识别 · 驱动已加载”。
2. 在安药点“绑定药盒”，在 12 秒内切到网站点“模拟短按 · 确认绑定”，等待绑定流程回执；然后在安药点“启用提醒”。未短按确认会超时，不会自动绑定成功。
3. 在安药展开“单格提醒”，为仓 1 设置 **08:01**。网站的虚拟时钟从 08:00 开始，将“虚拟时钟目标”设为 **08:01**，点“拨动虚拟时钟至目标”。应看到该仓到时状态、LED 提示及相应提醒模块处于执行状态。若本次会话时钟已经超过此时刻，请选择一个更晚的时刻；时钟不能倒退。
4. 保持到时任务未确认，在网站的端口卡片中依次尝试拔出、重新插入 **P1 屏幕、P2 震动马达、P3 音响**。拔出后该口输出关闭、能力撤销；重新插入后自动经历检测、受控供电、身份校验与驱动挂载。屏幕恢复显示；马达/音响立即应用当前仍在进行的提醒。用户不必重新设置计划或手动安装驱动。
5. 选择仓 1，点击“打开模拟仓盖”“关闭模拟仓盖”，确认盖位反馈变化。开合不会生成服药事实。只有显式点击“模拟本人确认服药”，才会新增一条标注为模拟的确认记录，并结束该仓本次模拟提醒；不会自动确认安药的真实服药事件或扣减真实库存。
6. 拔出 **P4 蓝牙**，安药顶部状态和网站连接应断开，虚拟药盒暂时不可发现。仅失去通信时，本地已启用的提醒与其余已供电模块应继续按既定任务工作；这和断开电源分别处理。重新插入蓝牙模块后会恢复可发现能力；返回安药主动扫描、选择并重新连接，不能绕过系统或用户授权自动配对。拔出 **P8 供电识别** 则撤销必要供电能力并断链，恢复后需重新连接。

P5 为 LED、P6 为开合检测、P7 为锁驱动。检测模块缺失时不能上报盖位；外设被拔出后该能力不能继续被当作可用。蓝牙离线后的本地提醒策略是软件演示，不能据此承诺真实硬件的离线提醒、备用电量或固件可靠性。计划与其他模块保持在各自的模拟会话中；不要把它解释为真实固件断电持久化验证。实际整机断电、EEPROM 保存、重新上电和故障恢复仍需固件及样机测试。

这些插拔使用软件身份描述符、CRC、驱动白名单和电流预算进行枚举。6 线通用外设接口与独立大电流电源接口属于自研 V0.9 候选，现有 Hi-PB1 的原厂屏幕、马达与蓝牙没有因此变成可拆模块。实际热插拔仍需验证触点顺序、软启动、总线隔离、限流、反灌、短路、连接器寿命及整机供电/温升；当前不能据此直接生产。更完整的接口说明随网站保存在 `web/docs/MODULAR_BUS_V09.md`。

## 开发浏览器验收与发行区别

`.qa/preview-server.mjs` 仅用于开发浏览器检查，只监听 `127.0.0.1`，预览端口以 CLI 日志为准。它向原页面响应注入 QA 桥，使用独立的 `.qa/temp-data.json`，并阻止真实蓝牙选择与设备来源事件。该开发目录不进入 EXE；它能验证同协议模拟往返与网页反馈，不能替代 Windows 原生窗口、系统蓝牙、安装或硬件验收。正式桌面包通过 Electron 的隔离预加载桥使用用户自己的本机数据目录。发行包的 `README.txt` 同时包含本文件的完整使用步骤。

Android 后台服务、闹钟策略、通知权限、健康接口与电池管理没有自动迁移。Windows 对应功能需要桌面代码逐项实现与验证。真实 BLE 操作仍需本人选择设备并测试，网页仿真和协议回执不能证明提醒实际响起、患者吞服或服药事实。本适配版没有完成真实蓝牙验收、程序签名或量产验证。
