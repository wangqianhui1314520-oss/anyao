## 这是什么

**安药是一款面向发作性睡病患者的智能药盒系统**：独立四仓药盒 + 手机 App + 兼容手表 + 家属端 + 电脑三维联动大屏，帮助患者解决**忘服与漏服**的烦恼。

想象一下：你刚小睡醒来，闹钟已经停了。拿起药盒，却想不起——**这顿药，到底吃没吃？**
对发作性睡病患者来说，这不是偶然的恍惚，而是每天都在发生的风险。安药把"吃没吃"变成一个可确认、可追溯、家属可见的事实。

### 核心功能

| 端 | 能力 |
|---|---|
| 📱 患者端 App | 四仓独立计划、按仓取药、本人确认服药才记账、库存与剩余天数、离线条码扫码登记、ISO 星期计划与修订历史 |
| 👨‍👩‍👧 家属端 | 区分未来计划 / 漏服 / 跳过 / 已补记，消除"还没到时间却全部按时吃完"的误报；联系记录需本人二次确认，不把"打开拨号界面"当作"已通电电话" |
| ⏰ 三端联动 | 到点手机（通知+响铃+震动+闪光）、药盒（仓灯+震动+响铃+屏幕）、手表同时提醒；**任意一端处理，三端一起结束** |
| 🔩 智能药盒 | 独立四仓独立内盖、BLE 07 帧协议（逆向 + 置信度标注）、低电量提示、开盖即同步 |
| 🖥️ 电脑大屏 | Node 联动平台 + three.js 三维药盒/手表实时镜像，**虚拟药盒演示无需真机** |
| 🪟 Windows 桌面 | Electron 适配版，原协议帧驱动虚拟药盒，双窗口联动演示 |

## 系统架构

```
┌──────────────────────────────────────────────────────────────┐
│                        安药 AnYao                             │
├──────────────┐   BLE 07 帧    ┌───────────────┐   BLE        │
│  安药 App     │◄────────────►│  智能药盒       │◄──────────► │
│  (Android)   │   置信度标注   │  独立四仓       │  小米手表    │
└──────┬───────┘               └───────────────┘              │
       │ 局域网扫码 / USB adb reverse（配对码每次更换）          │
       ▼                                                       │
┌──────────────┐   WebSocket    ┌───────────────┐             │
│  联动平台      │◄────────────►│  电脑三维大屏   │             │
│  Node :4200  │                │  three.js     │             │
└──────────────┘                └───────────────┘             │
                                                              │
┌──────────────┐   HTTP 注入适配  ┌───────────────┐           │
│  Windows 桌面 │◄──────────────►│  虚拟药盒会话   │           │
│  Electron    │    原协议 07 帧  │  模块插拔模拟   │           │
└──────────────┘                └───────────────┘
```

**数据边界**：联动平台只在本机与局域网内工作，不连接云端；扫码不上传图片；家庭同步走 `GET /api/capabilities` 字段协商，旧服务不会被静默丢弃新字段。

```
├─ mobile/             # Android 修复工程（com.anyao.app 1.1.0 基线）
│  ├─ web/             #   H5 页面（APK 提取 + 修复）
│  ├─ native/          #   9 个可审阅 Java 新源码（库存/相机/闹钟/扫码策略）
│  ├─ tools/           #   构建与真机测试脚本（APK SHA256 指纹核对后打补丁）
│  ├─ tests/           #   界面回归 + 真机原生 Store 测试
│  └─ vendor/          #   ZXing core 3.5.3（Apache-2.0，含许可证）
├─ desktop/            # Windows Electron 适配版（0.4.6）
│  ├─ src/             #   桌面源码
│  ├─ assets/          #   授权 APK 提取的 H5 资产（CRC/SHA256 清单）
│  └─ scripts/         #   prepare-assets.py（只读复核原资产）
└─ link-platform/      # 手机 × Watch S3 × 智能药盒 实时联动平台
   ├─ server.cjs       #   HTTP + WebSocket 服务（默认 :4200）
   ├─ devices.cjs      #   虚拟药盒/手表设备模型

   └─ public/          #   three.js 三维大屏（药盒/手表 GLB 模型）
```

## 🚀 快速开始

### 联动平台（电脑大屏，演示首选，无需真机）

```bash
cd link-platform
node server.cjs          # Node.js 18+，默认 http://127.0.0.1:4200
# Windows 双击「启动联动.cmd」或「一键演示全部功能.cmd」（约 2.5 分钟 26 步自动演示）
```

启动后大屏显示配对码；手机与电脑连同一 Wi-Fi，扫码加入即可三端联动。首次运行自动从 `app/empty-data.json` 生成演示数据；运行时数据目录 `data/` 不入库。

### Android 修复工程

```powershell
# 从仓库根目录运行（需 JDK 17 + Android SDK，路径见 mobile/README.md）
python -X utf8 mobile/tools/build-current.py
```

工具先核对输入 APK SHA256（`599372931707aab30fe00780ebbe1a9739cf307d123e89399a91717368f567d3`），再解包、打smali 补丁、编译 Java、合并 DEX、对齐签名。输出「安药验证」`com.anyao.app.qa` 1.1.0-repair.2 / versionCode 4，与原安药并存、数据独立。

### Windows 桌面适配版

```bash
cd desktop
node --test --test-isolation=none     # 桌面源码与打包约束测试
node .qa/preview-server.mjs           # 开发浏览器预览（仅监听 127.0.0.1）
```

正式包用 Electron 隔离预加载桥 + 用户本机数据目录；`scripts/prepare-assets.py --verify` 可只读复核原资产指纹。

## 🔬 技术亮点

1. **库存收据一致性状态机**：每次扣减保存实际数量与单位，撤销按当时收据回退；剂量说明（如"100mg"）绝不猜测片数；库存不足时记录服药但不产生负库存。
2. **精确闹钟前台服务**：修复本机锁屏时广播消费者被冻结、闹钟到点延后执行的问题；保留去重与计划取消，迁移旧广播闹钟。
3. **ISO 星期计划 + 修订历史**：按 ISO 星期（1=周一）生成计划与最多 31 天缺席历史；按日期生效的计划修订，改未来星期不改写历史。
4. **Camera2 + ZXing 离线扫码**：支持 EAN-13/EAN-8/Code128/二维码；扫码不上传图片、不自动打开网址、不推断医嘱。
5. **家庭服务能力协商**：`GET /api/capabilities` 声明已实现字段，旧服务静默丢弃新字段的路径被阻止。
6. **BLE 07 帧协议逆向**：药盒协议官方未公开，每条 opcode 标注置信度；非每日计划在页面与蓝牙写入前双重拒绝。
7. **三端状态机**：取药不自动记为已服，只有本人显式确认才生成服药记录；三端共用同一份状态。

## ⚠️ 已知边界（诚实声明）

- 网页仿真与协议回执**不能证明**提醒实际响起、患者吞服或服药事实；真实 BLE 操作需本人选择设备并测试。
- 蓝牙离线后的本地提醒策略是**软件演示**，不能据此承诺真实硬件的离线提醒、备用电量或固件可靠性；整机断电、EEPROM 保存、故障恢复仍需固件及样机测试。
- 模块热插拔（6 线通用外设接口）为自研 V0.9 候选设计，现有 Hi-PB1 原厂部件未变成可拆模块；实际热插拔需验证触点顺序、限流、反灌与连接器寿命。
- Windows 桌面适配未完成真实蓝牙验收、程序签名或量产验证；Android 后台服务、闹钟策略、健康接口需在桌面端逐项实现。
- 演示数据（含虚构家属联系人）仅用于演示，**不要当作正式用药计划**。
- 构建默认使用本机 Android debug keystore；发布到原包名需要合法的原签名密钥，密钥不包含在本仓库。
